# DDD-0001: Language
## Bounded context
Owns canonical action, graph, risk, plan and grant terms.
## Ubiquitous language
Uses canonical terms and no ambiguous safety booleans.
## Aggregates, entities, and value objects
canonical action, graph, risk, plan and grant terms. IDs and scores are immutable; lifecycle belongs to the aggregate root.
## Invariants
terms stay stable.
## Domain events
Publishes LanguageDefined.
## Context map
Facts cross owned ports; infrastructure adapters translate Cedar, RuVector and RVF.
## Ports and adapters
Infrastructure cannot gain authority beyond the typed result.
## Acceptance
Unit invariants plus a real orchestration or integration caller exercise this context.


## Detailed domain model
ActionBatch is a proposed unit of work; ActionIntent is one dependent step; CriticalReach is the de-duplicated high-criticality resource set; Intervention is removal of one action; Responsibility is its marginal reach reduction; RiskCertificate is a calibrated upper loss; EvidenceSeal is an RVF witness; ExecutionGrant is scoped, nonce-bound authority. Permit never means release by itself.

## Ownership and collaboration
cs-types and cs-policy-model define shared value semantics; adapters translate rather than redefine these terms. The language context exports facts through typed values and never leaks infrastructure handles across the context map. Commands are validated by the owning aggregate; downstream contexts consume immutable results. Failures remain explicit and are not converted into permissive booleans.

## Scenario acceptance
The frozen three-action deployment scenario must cross this context through its public API. Its unit invariant and at least one upstream or downstream collaboration are exercised by locked workspace tests; removing the context must create an observable ablation or eliminate a required release condition.
