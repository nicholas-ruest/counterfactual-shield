# DDD-0005: Memory
## Bounded context
Owns IncidentCorpus and Incident.
## Ubiquitous language
Uses canonical terms and no ambiguous safety booleans.
## Aggregates, entities, and value objects
IncidentCorpus and Incident. IDs and scores are immutable; lifecycle belongs to the aggregate root.
## Invariants
no secrets; fixed vector dimension.
## Domain events
Publishes IncidentsRecalled.
## Context map
Facts cross owned ports; infrastructure adapters translate Cedar, RuVector and RVF.
## Ports and adapters
Infrastructure cannot gain authority beyond the typed result.
## Acceptance
Unit invariants plus a real orchestration or integration caller exercise this context.


## Detailed domain model
Incident is the aggregate stored for recall, with validated severity, affected count, action kind, and bounded summary. IncidentRemembered and IncidentsRecalled are evidence events. Embeddings are value projections, not the domain identity. RuVector owns similarity mechanics while the memory context owns what an incident means.

## Ownership and collaboration
cs-incidents and cs-embedding feed cs-ruvector; the orchestrator consumes only incident IDs returned by real search. The memory context exports facts through typed values and never leaks infrastructure handles across the context map. Commands are validated by the owning aggregate; downstream contexts consume immutable results. Failures remain explicit and are not converted into permissive booleans.

## Scenario acceptance
The frozen three-action deployment scenario must cross this context through its public API. Its unit invariant and at least one upstream or downstream collaboration are exercised by locked workspace tests; removing the context must create an observable ablation or eliminate a required release condition.
