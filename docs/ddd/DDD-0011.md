# DDD-0011: Recovery
## Bounded context
Owns RecoveryPlan and Compensation.
## Ubiquitous language
Uses canonical terms and no ambiguous safety booleans.
## Aggregates, entities, and value objects
RecoveryPlan and Compensation. IDs and scores are immutable; lifecycle belongs to the aggregate root.
## Invariants
reverse order; visible failures.
## Domain events
Publishes RecoveryCompleted or RecoveryPartial.
## Context map
Facts cross owned ports; infrastructure adapters translate Cedar, RuVector and RVF.
## Ports and adapters
Infrastructure cannot gain authority beyond the typed result.
## Acceptance
Unit invariants plus a real orchestration or integration caller exercise this context.


## Detailed domain model
RecoveryPlan orders compensating actions in reverse dependency order. It is derived from the accepted batch and does not claim external compensation succeeded. RecoveryPlanned and RecoveryBlocked separate a valid plan from execution. Production adapters must make each compensation idempotent and report partial completion.

## Ownership and collaboration
cs-recovery owns order; runtime orchestration would invoke external compensators behind a separate port. The recovery context exports facts through typed values and never leaks infrastructure handles across the context map. Commands are validated by the owning aggregate; downstream contexts consume immutable results. Failures remain explicit and are not converted into permissive booleans.

## Scenario acceptance
The frozen three-action deployment scenario must cross this context through its public API. Its unit invariant and at least one upstream or downstream collaboration are exercised by locked workspace tests; removing the context must create an observable ablation or eliminate a required release condition.
