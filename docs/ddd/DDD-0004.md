# DDD-0004: Authorization
## Bounded context
Owns PolicyContext and PolicyDecision.
## Ubiquitous language
Uses canonical terms and no ambiguous safety booleans.
## Aggregates, entities, and value objects
PolicyContext and PolicyDecision. IDs and scores are immutable; lifecycle belongs to the aggregate root.
## Invariants
default deny; errors never permit.
## Domain events
Publishes PolicyEvaluated.
## Context map
Facts cross owned ports; infrastructure adapters translate Cedar, RuVector and RVF.
## Ports and adapters
Infrastructure cannot gain authority beyond the typed result.
## Acceptance
Unit invariants plus a real orchestration or integration caller exercise this context.


## Detailed domain model
PolicyReceipt is the anti-corruption result crossing from Cedar into the domain. Permit, Deny, and Error remain distinct so parsing/diagnostic failure cannot be confused with an explicit denial. The context evaluates every action and collapses the receipts with an all-permit invariant; it never issues execution authority.

## Ownership and collaboration
cs-cedar owns the adapter; cs-policy-model owns stable language; cs-verifier consumes the receipt. The authorization context exports facts through typed values and never leaks infrastructure handles across the context map. Commands are validated by the owning aggregate; downstream contexts consume immutable results. Failures remain explicit and are not converted into permissive booleans.

## Scenario acceptance
The frozen three-action deployment scenario must cross this context through its public API. Its unit invariant and at least one upstream or downstream collaboration are exercised by locked workspace tests; removing the context must create an observable ablation or eliminate a required release condition.
