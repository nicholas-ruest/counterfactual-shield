# ADR-0015: Telemetry
Status: Accepted
## Context
We need secret-free observation with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- logs
- payload traces
## Decision
Use structured counters and buckets.
## Tradeoffs
less payload detail.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with redaction, bound to the exact candidate commit.


## Detailed rationale
DecisionMetrics records evaluated, permitted, denied, recalled, critical-before, and critical-after counters without embedding secrets, action payloads, or policy text. Full request logging was rejected because privileged intents can contain sensitive identifiers. Metrics are derived after verification and do not influence release authority.

## Executed boundary and proof
The telemetry decision is implemented as a typed boundary, not a documentation-only convention. cs-telemetry accounting test and the metrics field in example output.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
