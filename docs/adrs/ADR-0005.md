# ADR-0005: Cedar
Status: Accepted
## Context
We need enterprise policy with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- custom rules
- OPA sidecar
## Decision
Use pinned deny-by-default Cedar.
## Tradeoffs
version coupling.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with permit, forbid and error, bound to the exact candidate commit.


## Detailed rationale
Cedar is the authoritative enterprise policy evaluator. Policies are parsed into PolicySet, action data becomes a typed Request, and Authorizer evaluates with an empty entity store for the frozen workload. Reimplementing Cedar predicates or treating policy text as documentation was rejected; parse and diagnostic failures are explicit denials.

## Executed boundary and proof
The cedar decision is implemented as a typed boundary, not a documentation-only convention. cs-cedar permit/deny test and NoCedar ablation, which eliminates the grant.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
