# ADR-0014: Configuration
Status: Accepted
## Context
We need explicit thresholds with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- hard-coded
- config file
## Decision
Use validated environment config.
## Tradeoffs
startup failures.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with invalid bounds, bound to the exact candidate commit.


## Detailed rationale
Risk ceiling, alpha, mitigation budget, and recall depth are a single validated ShieldConfig passed into the orchestrator. Scattered environment reads were rejected because tests could not bind one decision to one configuration snapshot. Zero budgets, zero recall, invalid probabilities, and non-finite boundaries are rejected before workload evaluation.

## Executed boundary and proof
The configuration decision is implemented as a typed boundary, not a documentation-only convention. cs-config boundary test and ShieldService construction failure propagation.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
