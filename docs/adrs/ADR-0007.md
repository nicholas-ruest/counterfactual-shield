# ADR-0007: Evidence
Status: Accepted
## Context
We need tamper detection with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- JSON hash
- audit DB
## Decision
Use RVF witness chain.
## Tradeoffs
integrity not truth.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with verify and tamper reject, bound to the exact candidate commit.


## Detailed rationale
The exact batch material and mitigation totals are hashed with SHAKE256 and placed in an RVF witness chain. Empty or mutated chains are invalid even if the upstream verifier treats an empty sequence as vacuously valid. Plain JSON receipts were rejected because they cannot bind plan and action material to independently checkable cryptographic evidence.

## Executed boundary and proof
The evidence decision is implemented as a typed boundary, not a documentation-only convention. cs-rvf tamper test, empty-chain ablation, and cs-verifier evidence_ok condition.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
