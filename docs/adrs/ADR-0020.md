# ADR-0020: Pinning
Status: Accepted
## Context
We need reproducibility with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- latest
- ranges
## Decision
Use exact SHAs and locked versions.
## Tradeoffs
maintenance.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with lockfile receipts, bound to the exact candidate commit.


## Detailed rationale
Cargo.lock is committed and validation uses --locked. Direct versions are pinned in the workspace, while upstream repository commits and licenses are recorded separately because crates.io package checksums are the executable source. Floating main branches and latest tags were rejected as unreproducible and unauditable.

## Executed boundary and proof
The pinning decision is implemented as a typed boundary, not a documentation-only convention. Cargo.lock, docs/integration-matrix.md, and cargo deny source policy.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
