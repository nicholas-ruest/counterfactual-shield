# ADR-0017: CLI
Status: Accepted
## Context
We need reproducible interface with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- CLI-centric
- none
## Decision
Use thin CLI over API.
## Tradeoffs
not architecture.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with quickstart, bound to the exact candidate commit.


## Detailed rationale
The CLI is intentionally thin and delegates to ShieldService. It supports example and evaluate, prints structured JSON, returns errors to the process, and rejects unknown commands. Business logic in command handlers was rejected because it would create an untested parallel authorization path.

## Executed boundary and proof
The cli decision is implemented as a typed boundary, not a documentation-only convention. cs-cli is the only executable target; dependency audit confirms all libraries retain callers.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
