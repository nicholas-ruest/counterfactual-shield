# ADR-0022: Security
Status: Accepted
## Context
We need untrusted upstream text with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- trust
- sanitize only
## Decision
Use opaque bounded inputs and default deny.
## Tradeoffs
rejects unusual inputs.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with injection and oversize, bound to the exact candidate commit.


## Detailed rationale
Unsafe Rust is forbidden, warnings fail CI, secrets are absent, IDs are validated, Cedar errors fail closed, RVF tamper/empty evidence fails, grants are scope-bound and one-use, and cargo deny checks advisories/licenses/sources. Silencing upstream advisories without rationale was rejected.

## Executed boundary and proof
The security decision is implemented as a typed boundary, not a documentation-only convention. deny.toml documents the one transitive unmaintained bincode waiver; raw cargo-deny evidence records all categories passing.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
