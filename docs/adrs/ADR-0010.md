# ADR-0010: Grant
Status: Accepted
## Context
We need analysis versus authority with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- boolean
- bearer token
## Decision
Use nonce-bound ExecutionGrant.
## Tradeoffs
nonce state.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with replay reject, bound to the exact candidate commit.


## Detailed rationale
ExecutionGrant contains the batch ID, one-time nonce, and evidence scope digest. The gate requires the combined verification report before consuming the nonce; reusing a nonce returns Replay. A reusable bearer token and a boolean permitted flag were rejected because they can be replayed against a changed plan or batch.

## Executed boundary and proof
The grant decision is implemented as a typed boundary, not a documentation-only convention. cs-executor-gate replay test and grant absence in safety ablations.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
