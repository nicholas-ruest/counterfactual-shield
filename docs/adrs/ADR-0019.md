# ADR-0019: Determinism
Status: Accepted
## Context
We need source-bound evidence with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- wall clock RNG
- global RNG
## Decision
Use explicit seed and ordering.
## Tradeoffs
limited variance.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with repeatable receipt, bound to the exact candidate commit.


## Detailed rationale
Identifiers use ordered collections; graph traversal de-duplicates resources; responsibility and plan ties use action ID; calibration losses are sorted with total_cmp; evaluation data and RVF timestamp are frozen. Wall-clock input and randomized embeddings were rejected because they prevent byte-for-byte evidence review.

## Executed boundary and proof
The determinism decision is implemented as a typed boundary, not a documentation-only convention. repeat tests and the stable combined objective of 28 on the frozen dataset.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
