# ADR-0024: MetaHarness
Status: Accepted
## Context
We need advisory evaluation with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- auto-promote
- omit
## Decision
Use bounded suite/replay, no promotion.
## Tradeoffs
availability risk.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with hash and readback, bound to the exact candidate commit.


## Detailed rationale
Darwin creates and verifies a repository-native suite; Flywheel applies a frozen advisory promotion gate to observed combined and enterprise-only evidence. Neither tool can override Rust tests, the structural checker, CI, or merge protections. Synthetic self-scoring without source-bound raw inputs was rejected.

## Executed boundary and proof
The metaharness decision is implemented as a typed boundary, not a documentation-only convention. Darwin hash e66652cfd99f and Flywheel fingerprint c5942e7c9bf8f28fe7af47a6ec3887d11eeb3f8c8e8601cc6a7a54969ea0b981.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
