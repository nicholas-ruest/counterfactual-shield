# ADR-0021: Dependencies
Status: Accepted
## Context
We need adapter isolation with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- unrestricted
- layers
## Decision
Use automated context direction.
## Tradeoffs
shared types constraint.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with no orphans, bound to the exact candidate commit.


## Detailed rationale
Crate dependencies follow bounded-context flow toward orchestration; domain crates do not import Cedar, RuVector, RVF, CLI, or runtime configuration. A single shared utilities crate and cyclic workspace edges were rejected because they obscure authority. Every library has a real dependent and the CLI is the sole executable leaf.

## Executed boundary and proof
The dependencies decision is implemented as a typed boundary, not a documentation-only convention. scripts/check-dependency-direction.mjs reports 23 crates, 50 local edges, and zero orphans.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
