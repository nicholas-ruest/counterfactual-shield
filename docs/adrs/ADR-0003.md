# ADR-0003: Resource graph
Status: Accepted
## Context
We need blast topology with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- tree
- external CMDB
## Decision
Use bounded directed typed graph.
## Tradeoffs
cycle controls.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with cycle-safe reachability, bound to the exact candidate commit.


## Detailed rationale
The graph models prospective propagation from each target resource to downstream critical resources. Reachability uses a queue and visited set so infrastructure cycles terminate deterministically. A flat criticality sum was rejected because it cannot distinguish an isolated secret from the same secret connected to a role, service, database, and public sink.

## Executed boundary and proof
The resource graph decision is implemented as a typed boundary, not a documentation-only convention. cs-resource-graph cycle test and the critical_before/critical_after fields in the ablation receipt.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
