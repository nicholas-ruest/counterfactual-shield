# ADR-0023: Ruflo
Status: Accepted
## Context
We need coordination only with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- runtime authority
- omit
## Decision
Use receipt with authority none.
## Tradeoffs
no completion inference.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with version and topology, bound to the exact candidate commit.


## Detailed rationale
Ruflo is limited to coordination provenance and has zero product or promotion authority. The requested 3.57.2 package was version-probed but its swarm command had a missing module; the governed installed 3.47.1 executed a one-agent hierarchical initialization. Pretending orchestration output is implementation evidence was rejected.

## Executed boundary and proof
The ruflo decision is implemented as a typed boundary, not a documentation-only convention. evidence/ruflo-execution-ledger.md records versions, command, swarm ID, outcome, and failover reason.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
