# ADR-0009: Mitigation
Status: Accepted
## Context
We need budgeted blast reduction with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- first fit
- exhaustive
## Decision
Use responsibility-per-cost greedy.
## Tradeoffs
not always optimal.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with small brute-force comparison, bound to the exact candidate commit.


## Detailed rationale
Mitigations are ranked by expected critical-reach reduction per unit cost and selected without exceeding the configured integer budget. Choosing only the highest responsibility was rejected because it can consume the budget while excluding multiple cheaper controls. Ties are deterministic by action identifier so evidence replay cannot change ordering.

## Executed boundary and proof
The mitigation decision is implemented as a typed boundary, not a documentation-only convention. cs-plan budget test and deterministic serialized plan inside the RVF payload.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
