# ADR-0013: Timeouts
Status: Accepted
## Context
We need bounded upstream work with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- unbounded
- global timeout
## Decision
Use per-stage budgets.
## Tradeoffs
slow valid work may fail.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with timeout paths, bound to the exact candidate commit.


## Detailed rationale
External adapters must be bounded by caller-owned cancellation and timeout budgets in production. The current local Cedar, RuVector, and RVF calls are synchronous and finite for the frozen corpus; adding artificial async wrappers was rejected because it would imply cancellation semantics the upstream APIs do not provide. The limitation is recorded for service deployment.

## Executed boundary and proof
The timeouts decision is implemented as a typed boundary, not a documentation-only convention. validation uses small local data; README lists distributed and live-adapter work required before production.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
