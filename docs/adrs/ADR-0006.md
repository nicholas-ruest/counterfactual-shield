# ADR-0006: Incident recall
Status: Accepted
## Context
We need analogous failures with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- keyword
- SQL
## Decision
Use RuVector VectorDB and deterministic embeddings.
## Tradeoffs
simple transparent vectors.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with insert/search/get, bound to the exact candidate commit.


## Detailed rationale
Incident memory uses the actual RuVector database API with a four-dimensional deterministic embedding, on-disk storage, insertion metadata, and HNSW search. A JSON scan and mocked vector port were rejected because neither exercises the upstream index. Recall is advisory for mitigation context but contributes measurably to the combined objective.

## Executed boundary and proof
The incident recall decision is implemented as a typed boundary, not a documentation-only convention. cs-ruvector real_insert_search and the end-to-end Combined versus NoRuVector delta.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
