# ADR-0012: Recovery
Status: Accepted
## Context
We need compensation with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- manual
- retries
## Decision
Use reverse-topological plan.
## Tradeoffs
compensation may fail.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with partial recovery, bound to the exact candidate commit.


## Detailed rationale
Recovery order is the reverse topological action order so dependents are undone before their prerequisites. Arbitrary cleanup order was rejected because revoking a role before stopping a dependent deployment can strand resources. Recovery produces typed rollback steps without claiming that the reference binary executes external side effects.

## Executed boundary and proof
The recovery decision is implemented as a typed boundary, not a documentation-only convention. cs-recovery reverse-order test and dependency-cycle rejection upstream.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
