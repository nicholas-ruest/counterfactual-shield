# ADR-0018: Evaluation
Status: Accepted
## Context
We need ingredient contribution with prospective safety, deterministic evidence and explicit authority.
## Viable alternatives
- one benchmark
- status table
## Decision
Use seven ablation modes.
## Tradeoffs
narrow frozen workload.
## Consequences
This boundary participates in the grant decision and fails closed. Downstream contexts receive typed results rather than ambiguous flags.
## Validation
Validate with degradation assertions, bound to the exact candidate commit.


## Detailed rationale
The frozen suite compares Combined, NoRuVector, NoRvf, NoCedar, NoRisk, EnterpriseOnly, and RuvnetOnly using the same batch, graph, incidents, calibration, and budget. Separate datasets were rejected because they confound ingredient effects. The objective rewards mitigation, recall, verified evidence, enterprise policy, and calibrated robustness.

## Executed boundary and proof
The evaluation decision is implemented as a typed boundary, not a documentation-only convention. evidence/raw/ablation.json and the integration assertion that every removal scores below Combined.

## Review trigger
Revisit this decision if its upstream API, trust boundary, workload distribution, or failure semantics change. A revision must preserve fail-closed authorization, deterministic replay, and an ablation that demonstrates what capability the decision contributes.
